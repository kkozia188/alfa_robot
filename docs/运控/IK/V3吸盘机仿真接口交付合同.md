# V3 吸盘机仿真接口交付合同（开发联调版）

本文件描述 **V3 吸盘机** 的仿真接入要求。模型以对应交付版本锁定的
`alfa_robot_description` V3 suction 资源为准；上层阶段 Action 的字段以中央
`robot_motion_interfaces/action/ExecuteMotionStage` 为准。运行中的仿真接口必须
实测符合本合同，不能仅靠 ROS 端点可发现判断兼容。

当前中央 `robot_interfaces/contract/endpoints.yaml` 的 R-IN-02 和 R-OUT-03
仍写二代 14 轴，不是本 V3 控制器 Profile 的验收证据。中央契约负责人需另行
版本化登记 V3 Profile；在登记前，本文件仅作为双方开发联调的明确约束，
不得冒充已经冻结的跨域生产合同。

## 关节集合

| 用途 | 关节与总数 |
| --- | --- |
| 完整模型反馈 | `left_joint1..7`、`right_joint1..7`（14），`updown`（1），`head_joint`、`head_pitch_joint`（2），`active_suspension_joint`（1），`caster01_joint..caster04_joint`（4），`wheel01_joint..wheel04_joint`（4）；合计 **26** |
| `whole_body` 规划/本 Demo 整组轨迹 | `left_joint1..7`、`right_joint1..7`、`updown`、`head_joint`、`head_pitch_joint`；合计 **17** |
| 不在本轨迹中的关节 | `active_suspension_joint`、四舵、四轮（9）；仍需在完整模型状态中提供实际反馈，不由 Motion 猜测或填零 |

`updown` 的模型范围为 **[-1.0, 0.0] m**；`active_suspension_joint`
为 **[-0.15, 0.0] m**。不得把旧仿真 `updown=[-0.5,0.5] m`
仅因行程同为 1 m 就直接写入新版模型。双臂旋转关节、头部与舵轮单位为 rad，
升降及主动悬挂为 m，车轮旋转角为 rad。吸盘通断不是模型关节。

## 话题与 Action

| 方向 | 端点 | 类型及要求 |
| --- | --- | --- |
| 上层 → Motion | `/motion/execute_stage` | `robot_motion_interfaces/action/ExecuteMotionStage`；只传阶段和 `base_link` 左右目标 Pose/抓取模式；按 PREGRASP → APPROACH → PLACE → HOME 串行 |
| 仿真/RT-Control → Motion | `/joint_states` | `sensor_msgs/msg/JointState`；`name` 和 `position` 至少覆盖上述 26 轴，`velocity` 按实际能力提供；按名称匹配，不假设数组顺序，含新鲜时间戳 |
| 仿真/RT-Control → Motion | `/tf`、`/tf_static` | 机器人本体 TF 由执行侧发布；不重复发布 Motion 中的虚构运动状态 |
| 仿真/RT-Control → Motion | `/control/safety_state` | 按中央 `robot_rt_control_interfaces/msg/SafetyState` 提供准入状态；不能用仿真场景可见替代安全就绪 |
| Motion → 仿真/RT-Control | `/whole_body_jtc/follow_joint_trajectory` | `control_msgs/action/FollowJointTrajectory`；同一 Goal 覆盖完整上述 17 轴，不接受部分关节轨迹 |
| Motion → 上层 | `/motion/readiness` | `robot_system_interfaces/msg/DomainReadiness`；状态源、Action 或安全准入失效时不可报 ready |

每个 FJT 点的 `positions`、`velocities`、`accelerations` 均须为 17 个有限值，
`time_from_start` 严格递增。控制器必须按名称接收完整集合、支持反馈和取消；
Motion 在下发前校验起点与 `/joint_states`，Action SUCCEEDED 后再核对实际末态。
一旦取消、超时或终态不明，不执行剩余缓存阶段。Motion 不控制真空泵或电磁阀；
APPROACH 与 PLACE 之间的吸取以及 PLACE 与 HOME 之间的释放由上层编排。

同一 ROS Domain、RMW/DDS、仿真时钟和匹配 QoS 必须随正式 Release 一并冻结。
仿真执行联调仅在上述 26/17 合同实测满足后允许 `execution_backend:=fjt`；
`execution_backend:=replay` 只能验证接口、规划和离线回放，不能证明已连接仿真执行器。

## 与仿真方旧版 0.3.0 的差异

旧版 `/robot/state/joints` / `/joint_states` 只含 25 轴，少
`active_suspension_joint`；其 `/whole_body_jtc/follow_joint_trajectory`
只收左右臂 14 轴，Updown 单独 Action、头部不在整组 Action，且只收位置字段。
旧版 Updown 范围也是 `[-0.5,0.5] m`。**旧版不能直接执行本 V3 Demo 的 FJT**；
双方要么升级仿真执行器到本合同，要么独立设计、评审并验证专用网关，
不能在 Motion 中静默删轴、补零、拆轨迹或改量纲。

## 首次联调验收

1. 比对安装的 URDF/配置哈希与本 Release 的描述资源及关节清单。
2. 核对 `/joint_states` 新鲜、26 轴齐全、数值和 Updown 范围合法；
   手动剔除主动悬挂轴时，Motion 应拒绝执行。
3. 核对 FJT Action 名称、17 轴集合及位置+速度+加速度支持；
   用旧 14 轴执行器测试必须被拒绝，不能假成功。
4. 验证单组双臂四阶段、阶段间吸放确认、取消与末态收敛；
   再跑全墙并逐组保留失败阶段与 Rerun。

本合同不声称旧仿真已完成升级，也不声称 25 箱整墙已在执行器上通过。
