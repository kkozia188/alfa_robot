# V3.1.1 远端流程整合说明

## 当前基线

- 活跃模型：`robot_v3.1.1-hybrid`，解析坐标系为 `arm_carriage`。
- 主编排：`v3_box_wall_grasp_demo.launch.py`；距离、箱号、左右臂、整墙/顺序场景均沿用远端流程。
- 当前解析模型：`V311Left/V311Right`。`V309Left/V309Right` 只供历史 FK/IK 回归，不再被活跃 Demo 调用。

## 能力合并

本地方案需要的能力已在远端主流程中复用，不复制第二套规划器：

- 每条关节边按配置分辨率插值，并对整机、环境和附着箱逐状态检查；
- 箱体在接触帧后由 world 移除，以 `tool0 -> box` 刚体变换附着，避免吸附瞬移或双份碰撞体；
- 失败结果保留失败阶段、原因、拒绝状态、碰撞对和相连的合法路径前缀，Rerun 不播放未连接的失败姿态。

## 本地方案保留

完整旧实现冻结在分支 `feat/motion-94-v3-local-extract-preserved`，提交 `e33146c`。
当前分支不保留第二套主编排，但在同一个远端入口提供显式研究策略：

```bash
ros2 launch alfa_robot_moveit_config v3_box_wall_grasp_demo.launch.py \
  x:=0.50 box_id:=9 arm:=left \
  wall_context:=target_only \
  post_extract_policy:=loaded_home
```

- `target_only` 只省略其他24个箱体，仓库环境碰撞仍保留；它不是正式整墙结果。
- `loaded_home` 在抽离后携箱回 Home 臂姿态，再单独校验 Updown 回0，全程保持箱体附着。
- 默认仍是 `wall_context:=full post_extract_policy:=rear_release`，即远端整墙与后置释放流程。
- 完整箱墙中若携箱 Home 本身与邻箱相交，`loaded_home` 必须失败，不能把它当作碰撞放宽或兜底成功策略。

## 验证

- V3.1.1 左右臂各随机256组关节状态，与安装后的 MoveIt URDF 逐组比较 FK，并执行解析 IK 回代。
- 最大解析 FK/MoveIt 位置差约 `8.4e-12m`；最大 IK 回代位置误差约 `6.3e-8m`，最大姿态误差约 `8.6e-8rad`。
- Release 下单次解析 IK 平均约 `12.4～13.1us`。
- `target_only + loaded_home` 连续三次真实 ROS 启动规划成功，并验证非法参数清理、规划节点异常退出联动关闭和服务下线。

## 已知边界

远端默认 `rear_release` 的旧后置落地目标按 V3.0.9 工作区设计。V3.1.1 可完成部分接近与抽离，但该固定后置目标可能直接无解析 IK；这属于任务目标需要重新标定，不是碰撞检查或解析几何误差。当前整合不通过关闭碰撞或移动障碍伪造成功。
