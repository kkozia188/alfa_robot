落地仓库 + 默认起终姿态（2026-09-12）

仓库内尺寸：高2.35m × 宽2.38m × 长4m。正墙位于+X，−X一侧开口；两侧墙、正墙、地板、顶棚共五个灰蓝半透明碰撞实体。箱墙居中靠正墙，底面Z=0，顶面2.04m，两侧各留17cm。

地面、箱墙底面、底盘落地基准统一Z=0。V3主动悬挂模型已在 base_footprint 中完成车轮落地对齐；本demo默认 model_ground_offset:=0.000005，只保留约5µm数值接触间隔，不是实机安全裕度。RViz、Rerun和规划器共用模型及环境几何。

起点和成功终点：左右臂J1～J7均为 [-90,-90,0,-90,0,0,0]°，共享 updown=0m、head_joint=0°，从SRDF home读取；不再用全零臂角。

五个环境实体参与初态、下降、IK、接触、抽出、负重返回和携箱升回的碰撞检查，不给地板或仓库增加碰撞豁免。check_environment:=true默认开启。

# 停止旧demo，重新source当前install后运行
ros2 launch alfa_robot_moveit_config v3_box_wall_grasp_demo.launch.py \
  x:=0.90 box_id:=5 arm:=auto
旧距离不能照搬：0.30m时home伸入箱墙；0.75m时携箱home碰剩余箱体。0.90m/5号左臂、9号右臂已有完整成功样例，不是最优距离或实测推荐。底排0～4需要下降约1.2946m，超过1m行程而拒绝，不会偷偷抬箱或关碰撞。

本轮固定0.90m全墙扫描成功17/25：5、6、8、9、10、11、13、14、15、16、18、19、20、21、22、23、24。0～4超行程，7/12/17接触路径未找到解；不是所有距离/策略的可达性证明。

自定义环境

默认文件 config/v3_box_wall_environment.json，通过 environment_file:=/绝对路径/scene.json 加载。每个盒体为唯一id、center和size（米，完整边长，world轴对齐）；必须有ground。默认 anchor:box_wall_back 相对箱墙背面中心XY，每个新距离请求同步移动仓库；绝对world坐标请去掉anchor或设为world。修改文件需重启。

非法尺寸/坐标/anchor/旋转/重复ID拒绝启动；失败请看 failure_stage/failure_reason 的具体碰撞对。仅做静态场景离散几何验证，未接实机。

先按箱高下降，携箱返回后升回默认高度

下降量 = max(0, 初始肩部中心Z − 箱中心Z − 0.25m)
落地后初始肩部中心Z ≈ 1.744634m
updown限位 = [-1, 0]m

下降按最多5mm采样检查整机碰撞；下降后升降固定，执行抓取和携箱RRT返回home臂角，最后 restore_default_height 携箱升回0m（同样逐步碰撞检查）。上升碰撞返回 return_lift_collision，不会跳过这一段冒充成功。

每个新请求重置完整箱墙和初态，是独立仿真，不是连续拆墙。成功后箱体仍附着，不放置释放。

01 / QUICK START启动一次，用服务重复发请求

两条指令的区别：ros2 launch 启动 demo 和可视化；ros2 service call 向已经运行的 demo 提交新的抓取请求，不是再启动一个 demo。

终端 A：启动并保留运行

cd ~/Sevenova/alfa_robot
source tools/ros_humble_env.sh
source ros2_ws/install/setup.bash
export ROS_LOCALHOST_ONLY=1
export ROS_DOMAIN_ID=188  # 先确保这个 domain 空闲，与实机隔离

ros2 launch alfa_robot_moveit_config v3_box_wall_grasp_demo.launch.py \
  x:=0.90 box_id:=5 arm:=auto shoulder_box_offset:=0.25

默认打开 RViz、Rerun，并自动计算和回放一次0号箱先下降再抓取。只想先看场景，可在启动参数中加 auto_run_once:=false。

终端 B：加载同一环境，再发请求

cd ~/Sevenova/alfa_robot
source tools/ros_humble_env.sh
source ros2_ws/install/setup.bash
export ROS_LOCALHOST_ONLY=1
export ROS_DOMAIN_ID=188  # 必须与终端 A 一致

ros2 service call /v3_box_wall_grasp_demo/plan_wall_box \
  alfa_robot_moveit_config/srv/PlanWallBoxDemo \
  '{x: 0.90, box_id: 5, arm: auto}'
每个新终端都要单独 source。进入仓库目录不等于加载接口。这里的0.30m是仿真成功样例，不是同事测量的结果或推荐最优距离。

02 / EXPECTED MOTION运行后，应该看到什么？

选择目标→规划→按需下降→接近→接触吸附→抽出→携箱返回
阶段画面中的预期表现
选择目标目标箱绿色，其余24箱橙色。RViz白色数字是固定墙格编号。
规划先计算完整路径；画面可能暂时不动，不代表卡死。
lower_to_box_height双臂默认home角随共享升降架下降；到目标高度后才开始抓取阶段。
到预接触点一只手臂避障移动到箱体正面前约5cm。
接触与吸附末端直线前进到箱体正面中心；目标箱随后成为末端附着物。
抽出手臂携箱沿远离箱墙的方向直线退回35cm，原墙格留下空位。
携箱返回手臂带箱避障返回home臂角，再携箱升回updown=0，停在默认姿态。
历史冻结版（align_height=false）：6号箱 / x=0.30m 已验证成功，用户也已确认动作正常。本机双视图验收录制包含87帧、完整接近—吸附—抽出—返回过程；后续规划路径及帧数可能变化。

底盘和转头轴不移动；另一只手臂的七个关节角保持不变，但会随共享升降架下降。最终箱体仍吸在手上，不会自动放下。RViz与Rerun播放相同结果，但播放速度不完全一致。

03 / SELECT A BOX箱体怎么指定？

最高层在上 · 每层沿世界坐标 +Y →
2021222324
1516171819
1011121314
56789
01234

最低层：0～4。屏幕左右随视角变化，以 RViz 编号为准。

  • x：车头参考平面到墙近面的距离，单位米，必须是有限正数。不是搬运距离。
  • box_id：0～24。行号 = id整除5（自底向上），列号 = id取余5（沿+Y）。
  • arm：left / right / auto。auto先左后右，找到完整路径就停止，不比较两臂最优性。

选择箱体就是修改服务请求里的 box_id，不需要在RViz拖动。成功计算后自动回放，不用再发送执行命令。

真正连续搬运还需要什么？

抓取0号 → 放到指定位置并释放 → 保留墙上的空位 → 从机器人当前姿态出发 → 抓取5号。

必要的待确认项：第一个箱体放在哪里？例如底盘上的指定位置，或外部固定放置点。需要明确放置位姿及过程，再补放置、释放和连续场景状态；不能把重置试验当成连续搬运。

05 / NO RESPONSE?没反应时，先看终端，再看画面

“画面没动”不是判据。先看终端B：请求是否发出、有没有返回结果。

请求尚未发出

service type is invalid

本终端没有识别新服务类型。先重新 source 环境；这不是抓取规划失败。

等待服务

waiting for service…

还没有发现服务。检查终端A的demo是否仍在运行，以及两边的ROS_DOMAIN_ID是否一致。

返回失败

success: false

请求无效、忙，或没有找到完整路径。看failure_stage与failure_reason，别只看机器人是否动。

规划成功

success: true

已找到完整路径，应自动回放。若画面不动，可能回放已结束，或可视化没有更新。

遇到类型无效：先确认接口能显示

cd ~/Sevenova/alfa_robot
source tools/ros_humble_env.sh
source ros2_ws/install/setup.bash
ros2 interface show alfa_robot_moveit_config/srv/PlanWallBoxDemo

正常应打印 x / box_id / arm 等请求字段和响应字段。若仍报错，请保留终端原始输出，不必反复重启可视化。

关闭终端后一直 waiting：本次已查明原因

2026-09-11 实际故障：启动命令写成了 arm:=auto~，末尾多了一个 ~。规划节点报 arm must be left/right/auto 后退出，但旧版仍保留可视化进程，造成“看起来运行中”的错觉。正确写法是 arm:=auto，不是抓取失败。
  1. 终端A必须保持运行。重开终端后，先按本页启动步骤重新 source、设置 domain 188 并启动 demo；只发服务请求不能启动服务。
  2. 检查第一条 ERROR/FATAL。新启动文件已在启动前拒绝非法 arm；规划节点退出时联动停止其余受 launch 管理的节点。独立 Rerun 窗口可能保留旧录制，不代表服务在线。
  3. 终端B重新加载环境再调用：与终端A使用相同 domain 和 localhost 设置；返回 success: true 才说明本次完整规划成功。
cd /home/astesia/Sevenova/alfa_robot
source tools/ros_humble_env.sh
source ros2_ws/install/setup.bash
export ROS_LOCALHOST_ONLY=1 ROS_DOMAIN_ID=188
ros2 service call /v3_box_wall_grasp_demo/plan_wall_box \
  alfa_robot_moveit_config/srv/PlanWallBoxDemo \
  '{x: 0.90, box_id: 5, arm: auto}'

停止时建议在终端A按 Ctrl+C 并等待退出，再关闭窗口。突然关闭后，服务发现可能短暂缓存旧记录；不要把“窗口还在 / service list 有名字”当成真实请求已成功。

三处反馈入口

  • RViz状态文字：CALCULATING 计算中；SUCCESS 找到路径；FAILED ... 失败及原因。
  • Rerun的Task status：显示计算状态、成功/失败、失败原因。
  • 终端A启动日志：calculation started 表示开始；calculation completed: SUCCESS/FAILED 表示计算结束。
SUCCESS = 规划成功，不是实机搬运完成。规划期间状态发布会暂停；回放结束后画面停住，不会一直循环。如果已显示开始但迟迟没有完成，应保留日志排查，不要连续堆积新请求。

06 / FAILURE DETAILS失败原因怎么看？

先看服务响应这几个字段，暂时不必通读很长的 result_json：

success: false
selected_arm: ''
failure_stage: cartesian_approach
failure_reason: '...collision:neighbor_box_3<->right_joint7'
历史结果已更新：8号、14号右臂曾在接触最后一步报末端与邻箱碰撞；这是零数值间隙版本的结果。2026-09-11修复贴面数值问题后，冻结版固定高度（align_height=false）下两者均已规划成功，不要把旧失败原因当成当前固定结论。

10号可以、14号不行，是只算了一只手吗？

不是。修复前10号由模型的 left 臂完成；14号的 auto 已尝试两臂，左臂预接触无逆解，右臂最后一步报 right_joint7 / neighbor_box_9 碰撞。臂名以模型为准，不以屏幕左右判断。

定位到导出末端网格与名义TCP接触面约0.1微米的偏差。新demo使用1微米仿真数值间隙，并同步修正附着位置，避免吸附时箱体跳动；没有缩小碰撞体或放开邻箱碰撞。该数值不是实机吸盘标定或安全距离。

当前 x=0.30m 实测：10号 auto → left → success；14号 auto → left失败 → right成功，显式 arm: right 也成功。终端A现在逐臂打印 arm=... SUCCESS/FAILED。
ros2 service call /v3_box_wall_grasp_demo/plan_wall_box \
  alfa_robot_moveit_config/srv/PlanWallBoxDemo \
  '{x: 0.90, box_id: 14, arm: auto}'
failure_stage含义
invalid_requestx、箱号、arm等输入不合法。
busy检测到已有待处理规划；当前同步串行服务也可能让并发请求排队。
height_alignment_limits按公式计算的升降目标超出[-1,0]m；本次拒绝下降。
height_alignment_collision下降采样发现整机碰撞或关节越界；本次拒绝下降。
initial_state机器人初始状态存在碰撞。
return_goal携箱返回目标状态存在碰撞。
precontact_ik没有找到可用的预接触逆解候选。
cartesian_approach直线接触过程失败。
attach_box箱体附着后的状态检查失败。
cartesian_retreat携箱直线抽出过程失败。
rrt_to_precontact初态到预接触点的避障规划失败。
rrt_return携箱返回的避障规划失败。

auto两臂都失败时：顶层失败原因来自最后尝试的臂；两只臂的结果在 result_json → attempts 中。失败时 selected_arm 为空。

未找到路径 ≠ 绝对不可抓取。它仅代表当前固定初态、抓取策略、模型、离散碰撞检测和有限搜索预算下，没有找到完整路径。失败时可能回放诊断片段，片段不代表抓取成功。

07 / REPORT A PROBLEM把这三项发来，就能先定位问题

  1. 请求参数：x、box_id、arm，以及是否刚重新启动demo。
  2. 终端B结果：是一直等待，还是返回了success、failure_stage、failure_reason。
  3. 终端A最后几行日志：若success=true但画面没有动作，再附RViz/Rerun截图。

08 / SCOPE & REFERENCES当前版本的边界

  • 场景：5×5固定墙，默认箱体0.30×0.40×0.40m，横竖间隙1cm。默认墙居中靠正墙、底面Z=0；地面/底盘同为落地零基准，仓库内尺寸4×2.38×2.35m，−X端开口。
  • 底盘基准：默认遍历V3完整移动底盘（车架、主动悬挂、脚轮和车轮）的碰撞网格顶点；按四轮轴心定义 base_footprint 后，world最大X约为+0.500m。可通过启动参数 chassis_front_x 显式标定覆盖前沿，实测基准仍需对齐。
  • 状态：正式SRDF home起终姿态，升降先按公式下降，抓取期间固定，携箱返回后升回0；头部固定，不搜索底盘/共享轴。
  • 任务：默认采用远端主编排完成单次抽箱、后置和释放；显式 target_only + loaded_home 仅用于本地携箱回Home研究。没有实机执行。
  • 安全边界：成功仅表示模型内找到几何路径，不是连续碰撞、吸附可靠性、载荷/动力学或实机安全证明。
