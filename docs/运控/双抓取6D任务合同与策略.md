# 双抓取 6D 任务合同与策略

## 1. 对外唯一任务输入

整机通过 `/robot_motion/run_dual_grasp_task` 发送 `RunDualGraspTask`：

```yaml
request_id: string
left:
  pose_6d: {x, y, z, roll, pitch, yaw}
right:
  pose_6d: {x, y, z, roll, pitch, yaw}
execute: bool
```

- `pose_6d` 始终是箱体朝向机器人的正面中心位姿，不是吸盘工具接触位姿；顶吸任务也传正面中心。
- 坐标系固定为 `base_link`。
- 位置单位为米，RPY 单位为弧度。
- 位姿局部 `+Z` 从机器人指向箱内；算法据此换算顶面中心和顶吸工具朝向。
- 当前标称正面姿态 RPY 为 `(π, -π/2, 0)`，等价四元数 `(x,y,z,w)=(√0.5,0,√0.5,0)`；
  实测姿态允许有偏差并会原样进入 IK，不能再绕正面法向额外翻转 180°。
- `execute=false` 表示只规划、不执行。
- 箱号、吸附模式、排数、IK 搜索、候选数量、碰撞对象、负重姿态族和规划器参数均为系统内部信息，不进入整机任务合同。

接口定义：

- `ros2_ws/src/robot_motion_internal_interfaces/srv/RunDualGraspTask.srv`
- `ros2_ws/src/robot_motion_internal_interfaces/msg/GraspTarget.msg`
- `ros2_ws/src/robot_motion_internal_interfaces/msg/Pose6D.msg`

## 2. 排数识别与策略分类

算法只读取两个正面中心 6D 位姿。当前五排箱高为 `0.4m`，标称正面中心 `z` 从上到下为
`1.597906、1.197906、0.797906、0.397906、-0.002094m`。输入匹配到最近排中心，默认允许
`±0.12m` 高度残差；残差超过阈值时拒绝任务，不猜测排数。阈值小于半排高度，因此不会让
同一个高度同时属于相邻两排。识别只用于选策略，实际测得的 `x/y/z/RPY` 原样进入 IK 和场景。

第 1～3 排使用侧吸，第 4～5 排使用顶吸。一侧落在侧吸排、另一侧落在顶吸排时，内部统一
升级为双顶吸，并由各自正面中心位姿换算顶面接触位姿。禁止通过箱号推断策略。

| 内部分支 | 判断 | 左臂要求 | 右臂要求 |
| --- | --- | --- | --- |
| 等高双侧吸 | 两侧最终均为 `front` 且高度差不超过容差 | 必须完全抽离；保持原有侧邻箱脱离判据；优先后退 | 同左臂 |
| 左高双侧吸 | 两侧最终均为 `front`，左侧更高 | 必须完全抽离；保持原有判据 | 必须完全抽离；只以高 `0.40m` 的参考箱 x-z 侧面投影作为脱离目标，抽离时优先上抬 |
| 右高双侧吸 | 两侧最终均为 `front`，右侧更高 | 必须完全抽离；只以高 `0.40m` 的参考箱 x-z 侧面投影作为脱离目标，抽离时优先上抬 | 必须完全抽离；保持原有判据 |
| 等高双顶吸 | 两侧均为 `top_suction` 且高度差不超过容差 | 必须完全抽离；优先上抬，允许后退和转向 | 同左臂 |
| 左高双顶吸 | 两侧均为 `top_suction`，左侧更高 | 尽可能抽离，不强制完全抽离 | 必须完全抽离 |
| 右高双顶吸 | 两侧均为 `top_suction`，右侧更高 | 必须完全抽离 | 尽可能抽离，不强制完全抽离 |
| 跨侧吸/顶吸排 | 一侧属于第 1～3 排、另一侧属于第 4～5 排 | 内部转为顶吸后按左高/右高策略处理 | 同左臂 |

系统使用固定箱体尺寸（深 `0.3m`、宽 `0.4m`、高 `0.4m`），从正面中心位姿计算顶面中心；
侧吸则直接使用输入正面中心。顶吸换算沿实测箱体朝向完成，不会把位置吸附回标称网格。

分类实现：`ros2_ws/src/robot_motion_runtime/robot_motion_runtime/dual_grasp_strategy.py`。

## 3. 策略如何进入完整规划

1. `dual_grasp_task_adapter_node` 校验 6D 数值、匹配排数、决定吸附方式并生成真实工具接触位姿。
2. 内部 `RunDualArmPoseTask` 携带 `DualGraspStrategy`。
3. 编排层把策略传给 `PlanExtract`。
4. 完整 C++ 抽离算法使用每侧的 `require_full_detachment`、`front_clearance_levels` 和方向优先级：
   - 必须抽离的一侧，终点不满足脱离条件就失败；
   - 高侧最佳努力的一侧，可以接受已有实际进展且全程无碰撞的路径；
   - 不等高侧吸的矮侧使用 `front_clearance_levels=2`，只检查与高 `0.40m` 参考箱的 x-z 投影是否完全分离，不再同时要求离开自己的原箱位；
   - 使用 `updown` 抽离不等高任务时，`updown` 与矮侧六轴同步运动；矮侧先尝试纯上抬，无有效解析 IK 或发生碰撞时再依次尝试斜上后退、仅后退；
   - 任何使用 `updown` 的抽离在竖直阶段结束后，固定 `updown`，再让双臂末端向车侧后抽半个箱深（`0.15m`）；每步优先纯后抽，必要时只允许毫米级上让和小角度姿态调整，并枚举解析 IK 分支后统一做整机、附着箱和场景碰撞检查；
   - 两侧任何时刻都不能跳过机器人、附着箱和场景碰撞检查。

内部策略消息：

- `ros2_ws/src/robot_motion_internal_interfaces/msg/DualGraspStrategy.msg`
- `ros2_ws/src/robot_motion_internal_interfaces/msg/ArmExtractPolicy.msg`

完整 C++ 抽离实现：

- `ros2_ws/src/alfa_robot_moveit_config/src/box_pose_rrt_extract_planner.cpp`
- `ros2_ws/src/alfa_robot_moveit_config/src/dual_arm_planner_node.cpp`

## 4. 箱号的剩余边界

`task_thread.py`、`extract_sequence_rerun.py` 等实验工具仍可用任务编号或箱号生成测试用的左右
正面中心 6D 位姿和结果标签，但发给算法线程/正式服务的消息不含这些字段。算法侧不再用箱号
决定任务策略或碰撞几何：

- 集装箱始终使用算法配置中的基准位置，A/B 偏移不会移动集装箱；
- 算法根据左右正面中心 6D 位姿和已知箱体尺寸建立两只原位箱体；
- 箱墙开口、左右/中间填充、整面后挡墙和抽离终点判据均由这两只原位箱体生成；
- 吸附后箱体按内部推导的吸附方式附着到末端，随机器人一起进入碰撞检测；
- 旧 C++ monitor 接口中的左右整数只固定为内部碰撞体槽位标签，不来自任务输入，也不参与策略或场景位置计算。

运行时 `PlanExtract` 服务目前仍是可观测的 shortcut 过渡实现，不等价于完整 C++ 箱体位姿 RRT。算法验收继续使用 `dual_arm_planner_node` 的完整流程；在 C++ rollout 完全迁入独立 `PlanExtract` 后，外部 6D 服务链才能替代该验收入口。不要把过渡服务的成功率当成完整算法成功率。

## 5. 验证

- 策略分类单测覆盖双侧吸、等高双顶吸、左高、右高和保留逐臂模式的混合吸附，共 8 项。
- 核心、场景、运行时和完整规划共 39 项回归测试通过。
- 顶吸 7 组使用全 `updown` 范围补测，7/7 完成完整 IK、抽离和负重规划。
- 不等高任务日志已确认高侧进入 `collision-free best-effort path`，低侧仍执行强制脱离检查。
- 2026-08-01 居中 13 组复测确认第 1～3 排逐臂使用侧吸、第 4～5 排逐臂使用顶吸，混合任务未降级；所有成功的 `updown` 抽离均记录到 `post_lift_retreat_x=0.15m`。完整流程成功 9/13，失败保留真实碰撞或负重规划原因。
